## 1. 주제 선정 배경

### 주제

옵시디언 볼트를 그대로 쓰는, 그림 자료 중심의 iPad/Mac(+iPhone) 네이티브 개인 위키.

### 선정 배경

- 관찰한 변화: 노트테이킹 앱 시장이 고성장 중(2026년 약 133억 달러 전망, CAGR ~20%)이며, 태블릿+스타일러스 창작 인구 증가와 로컬 우선·평문 파일 소유권 선호가 함께 커지고 있다.
- 사용자의 현재 불편: 텍스트 노트앱(Obsidian 등)은 이미지가 홀대받고, 레퍼런스 툴(Eagle, PureRef)은 노트·링크가 없다. 두 시장의 교차 영역이 비어 있다.
- 지금 해결해야 하는 이유: Obsidian이 Canvas 등 비주얼 기능을 흡수 중이고 refern·Kosmik 등 신규 레퍼런스 툴이 진입 중 — 틈새가 닫히기 전에 선점할 시점.
- 근거 및 출처: `docs/research/market.md` 3.2~3.6 (확인일 2026-08-10).

## 2. 문제 정의

### 핵심 문제

미술 전공자·시각 창작자가 아이디어와 레퍼런스를 텍스트+이미지로 기록하려 할 때, 노트 도구에서는 이미지를 넣고 태그하고 다시 찾는 것이 어려워 저장을 포기하거나("avoid adding images to my vault"), 저장해도 재발견에 실패하고, 결국 한 폴더 덤핑으로 귀결된다.

### 현재 해결 방식과 한계

- 현재 사용하는 방식: Apple 메모(캡처), Obsidian(텍스트 위키), Eagle/PureRef(이미지 뷰어), Pinterest/사진 앱 폴더 덤핑의 조합.
- 장점: 각 도구가 자기 영역(캡처, 링크, 이미지 열람)에서는 잘 동작한다.
- 해결되지 않는 문제: 이미지에 태그·메모를 붙여 검색할 수 없음(옵시디언 포럼 다수 발언), 도구 간 이전 시 링크·첨부 유실(락인 트라우마), 텍스트와 이미지가 한 지식 구조 안에서 연결되지 않음. Apple 메모는 위키링크·평문 소유권이 없어 "쌓이는데 연결이 안 된다".

### 문제 가설

- 가설: 미술 창작자는 이미지가 1급 시민인(첨부·보기·태그·검색) 옵시디언 호환 네이티브 위키가 있으면, 기존 도구 조합을 이 앱으로 대체·보완할 것이다.
- 근거: 페인포인트 1·2·3(이미지 홀대·재발견 실패·한 폴더 덤핑, `docs/research/painpoints.md`), 경쟁 비교표에서 교차 영역 공백 확인(`market.md` 3.3·3.4 O).
- 검증 방법: MVP(TestFlight)를 미술 전공생·창작자에게 배포, "볼트를 열어 이미지 첨부 노트를 작성하고 1주 후 검색으로 재발견하는가"를 사용 로그·인터뷰로 확인.
- 검증 상태: 미검증 (커뮤니티 발언 기반 부분 근거만 확보 — 국내 사용자·직접 인터뷰 없음).

## 3. 사용자 정의

### 핵심 사용자

그림 레퍼런스와 작업 아이디어를 iPhone으로 수시로 캡처하고, iPad/Mac에서 정리·열람하며 작업하는 시각 창작자(미술 전공생, 일러스트레이터, 컨셉 아티스트). 폴더 분류보다 태그·링크로 사후 정리하길 원하고, 자료의 파일 소유권을 중시한다.

**타겟 시장: 글로벌 (영어권 우선 + 한국).** 페인포인트 근거가 영어권 커뮤니티(옵시디언 포럼·Substack)에서 나왔고, 옵시디언 사용자 기반 자체가 글로벌이며, 국내 단독으로는 도달 가능 시장이 협소하다. 출시는 영어+한국어 동시 지원을 전제한다 (시장 규모 추정은 `market.md` 3.5).

### 페르소나

- 이름: 김서연 (가상)
- 역할·상황: 미대 회화과 3학년. 과제·개인 작업 병행, iPhone+iPad 사용, 옵시디언을 써봤거나 쓰는 중.
- 목표: 수업·전시·SNS에서 본 레퍼런스와 떠오른 아이디어를 한 곳에 모으고, 새 작업 시작 시 관련 자료를 바로 되찾기.
- 주요 불편: 이미지는 사진 앱·Pinterest에, 글은 메모 앱에 흩어짐. 모아둔 이미지를 태그로 못 찾음. 분류 체계 세우다 지침.
- 현재 행동과 도구: Apple 메모로 급히 캡처 → 사진 앱 폴더 덤핑 → 필요할 때 스크롤로 뒤짐.
- 기대 결과: 캡처는 3초 안에, 정리는 나중에 태그·링크로, 검색 한 번에 이미지+노트 재발견.
- 근거: 커뮤니티 조사(옵시디언 포럼·Substack, `painpoints.md`) + 가설. 직접 인터뷰·설문 미실시 — 페르소나 세부는 미검증 가설임.

### POV

**시각 창작자는 이미지와 텍스트를 한 지식 구조에서 연결·재발견할 수단이 필요하다. 왜냐하면 캡처는 이미 쉽지만, 쌓인 자료를 태그·링크 없이 다시 찾는 것은 실패하기 때문이다.**

### HMW

**우리는 어떻게 하면 시각 창작자가 캡처한 이미지·아이디어를 분류 강요 없이 나중에 연결하고, 새 작업 시작 시점에 바로 되찾도록 도울 수 있을까?**

## 4. 서비스 콘셉트

### 한 줄 정의

미술 창작자를 위해, 옵시디언 볼트(평문 .md)를 그대로 쓰면서 이미지를 1급 시민으로 다루는 iPad/Mac(+iPhone) 네이티브 위키 — 마찰 없는 캡처와 태그·위키링크 기반 재발견을 제공한다.

### 핵심 가치

1. **이미지가 1급 시민** — 첨부·보기·태그·검색이 텍스트 노트와 동급 (페인포인트 1·2·3 직접 해결).
2. **소유권과 호환** — 평문 .md + 로컬 이미지 파일, 옵시디언 볼트 그대로 사용 = 갈아타기·이탈 비용 제로 (페인포인트 4).
3. **캡처는 즉시, 구조는 나중에** — iPhone에서 던져넣고 iPad/Mac에서 태그·링크로 사후 연결. 폴더 분류 강요 없음 (페인포인트 3·5).

### 차별화 방향

- 기존 서비스와 다른 경험: Obsidian은 이미지 워크플로에 설정 부담, Eagle은 iPad·노트 없음, Milanote는 평문 없음·웹 기반, Apple 메모는 링크·소유권 없음. ArtObsidian은 네 가지 공백을 하나로 채운다.
- 사용자가 차이를 체감하는 지점: 설치 직후 설정 없이 기존 옵시디언 볼트를 열어, 이미지 붙은 노트를 iPad에서 훑고 검색으로 되찾는 순간.
- 차별화 근거: `market.md` 3.3 비교표·3.6 결론 — "그림 자료를 보면서 쓰는 개인 위키"를 iPad/Mac 네이티브로 제공하는 제품은 조사 범위 내 미확인.
- 포지셔닝 주의: Obsidian과 경쟁이 아닌 **보완** — 같은 볼트를 쓰는 미술 특화 프론트엔드. "옵시디언에서 되는데 왜?"에 대한 답은 "설정 없이 바로 되는 이미지 중심 네이티브 경험".

### 핵심 사용 시나리오

1. 사용 전 상황: 전시장에서 마음에 드는 작품을 봤다. 지금은 사진만 찍고 넘어간다.
2. 서비스 진입 계기: iPhone에서 ArtObsidian을 열어 사진과 한 줄 메모를 인박스 노트로 던져넣는다 (3초, 분류 없음).
3. 핵심 행동: 저녁에 iPad로 볼트를 열어 그 노트에 태그(#색채 #유화)와 `[[진행중 작업]]` 위키링크를 단다.
4. 서비스 반응: 노트·이미지가 태그와 링크로 연결되고, 검색과 관련 노트에 즉시 잡힌다.
5. 사용 결과: 몇 주 뒤 새 작업을 시작할 때 태그 검색 한 번으로 관련 레퍼런스·메모를 모아 보고 바로 작업에 들어간다.

## 5. Feature List와 MVP

상세 우선순위·완료 조건은 `docs/prd/features.md`, 순서·의존관계는 `docs/prd/roadmap.md` 참조.

**MVP = P0 (5개):**

1. 마크다운 편집/읽기 — 평문 .md 저장, 옵시디언 볼트 호환
2. `[[위키링크]]` + 자동완성
3. 노트 목록/폴더 트리 + 텍스트 검색
4. 이미지 첨부·보기 — 사진/파일에서 첨부, 노트 내 렌더링, 옵시디언 임베드 문법 호환
5. 볼트 열기/로컬 저장 — 로컬 전용으로 완전 동작 (동기화 없이도 성립)

**MVP 제외 (P1 이후):** 태그, 빠른 검색(Cmd+K), zip 백업/복원, iCloud 동기화(옵션), 그래프 뷰, 유사도 관련 노트, 이미지 태그·갤러리 고도화.

**정책 결정 (확정):** 앱 구독 없음. 동기화는 iCloud Drive 기반이되 옵션 — 미구독자는 로컬 전용 + zip 백업(P1)으로 안전망 확보. 자체 클라우드 서버는 하지 않음 (`market.md` SWOT T의 애플 스토리지 비용 리스크 대응).
