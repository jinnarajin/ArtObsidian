## 1. AI 사용 중 막힌 지점

- 무엇을 하려던 중이었는가? 리서치(시장조사·페인포인트) → 중간보고서 리뷰 → 승인 후 기획(PRD·기능 우선순위·로드맵) 단계 진행.
- AI는 어떤 응답이나 결과를 냈는가? 대체로 계획대로 진행. 다만 (1) 리서치 에이전트가 Reddit·X 크롤링 차단으로 원문 인용을 못 얻었고, (2) 시장 규모 섹션이 3.4 앞에 3.5로 삽입되는 순서 꼬임, (3) decisions.md 편집 중 날짜 헤더(2026-08-07)를 실수로 지운 일이 있었음.
- 기대한 결과와 실제 결과의 차이는? 큰 차이 없음. 사용자 지적으로 고쳐진 것: 유료 차트 vs 무료+해금 모델의 모순, 번역투 한국어, 시장 크기 분석 누락, 국내 한정 타겟.
- 문제의 원인: (1)은 환경(크롤링 차단), (2)(3)은 AI의 편집 부주의, 모순·누락은 AI의 초안 한계 + 사용자 리뷰로 잡힘.
- 판단 근거: 헤더 삭제는 diff 확인 중 직접 발견해 즉시 복구, 순서 꼬임은 스크립트로 재정렬.

## 2. 지식 수준에 따른 토큰 소비량과 소요 시간 비교

### 2.1 잘 아는 분야 작업

- 작업 내용 / 토큰 소비량 / 소요 시간: 옵시디언·마크다운·앱 방향 논의(iCloud 동기화 구조, 백업 설계) — 대화 몇 턴으로 즉시 결정. 서브에이전트 불필요.

### 2.2 모르는 분야 작업

- 작업 내용 / 토큰 소비량 / 소요 시간: 시장조사·페인포인트·출시 전략 등 웹 리서치 — 서브에이전트 7회, 회당 약 4.7만~7만 토큰(합계 약 39만), 회당 1.5~8.5분. 검증(가정 비율 데스크 검증)에 별도 5.3만 토큰.

### 2.3 차이 분석

- 리서치성 작업이 토큰의 대부분을 차지 — 웹 검색·본문 확인·출처 정리가 비쌈.
- 잘 아는 분야(자기 워크플로·애플 생태계)는 사용자·AI 모두 빠르게 판단, 프롬프트도 짧았음.
- 모르는 분야(시장 규모 추정)는 "추정 → 사용자 의심 → 프록시 검증 → 수치 하향"의 재작업 루프가 발생 — 처음부터 검증까지 한 번에 시키는 게 효율적이었을 것.

## 3. 프롬프트 작성과 AI의 해석

### 3.1 실제 프롬프트

```
[최초 프롬프트]
리서치/기획팀 가동해줘. 산출물은 이 레포(ArtObsidian)에 저장.
기준 문서: ~/Documents/projects/artobsidian-lab/docs/spec.md (리서치·기획 단계),
시장조사 양식 TEMPLATE.md, 기획안 양식 TEMPLATE.md
작업 순서: 1. 리서치팀 market.md + painpoints.md → 2. HTML 중간보고서(리뷰 후 진행 결정)
→ 3. 승인 후 기획팀 prd.md + features.md + roadmap.md
규칙: 서브에이전트 병렬, 기획은 승인 후에만, research/kickoff 브랜치 + PR
```

```
[주요 수정 프롬프트]
- "좋긴한데 이러면 애플 메모도 같이 정리할 수 있어?" (경쟁표에 기본값 대안 추가)
- "icloud drive 구독을 잘 안하는데 하는 사람이 많은지도 리서치를 해줘" (보급률 조사)
- "괜찮은 기획인데 부족한 부분은 시장 조사 및 크기 분석을 못했네. 그리고 타겟자체가 국내만 하기엔 아니지 않나" (TAM/SAM/SOM + 글로벌화)
- "핵심 비율 2개는 직접 통계 없는 추정임을 ... 이거 일단 검증해봐" (프록시 검증 → SAM 절반 하향)
- "보고서 형식으로 하되 언어는 쉬운 한국어로 변환해줘" (번역투 제거, 이후 상시 규칙화)
```

### 3.2 명문화한 요구사항과 명문화하지 않은 부분

명문화한 부분

- 산출물 파일·양식·완료 기준(출처·인용 수), 승인 게이트, 브랜치·PR 규칙, 공통 P0 고정 3종

명문화하지 않은 부분

- 시장 크기 분석(TAM/SAM/SOM), 타겟 지역, 문서의 언어 톤, 수익 모델·마케팅 전략

### 3.3 명문화하지 않은 부분에 대한 AI의 해석

- 도움이 된 가정: 이미지 P0 승격 제안(리서치 근거 기반), Apple 메모를 "기본값 대안"으로 분석, 구독 장벽을 제3자 비용 리스크로 구분.
- 의도와 다르게 해석된 것: 보고서 어투를 번역투 한국어로 작성("1급 시민" 등), 시장 규모 분석을 양식에 없다는 이유로 생략, 검증 보완을 국내 한정으로 잡음.
- 다음에 명문화할 것: 언어 톤(쉬운 한국어 — 메모리에 규칙화 완료), 양식 외 필수 분석 항목(시장 크기), 타겟 지역.

## 4. 시행착오 과정

### 시행착오 1: Reddit·X 원문 인용 실패

- 겪은 어려움: 페인포인트 조사에서 Reddit·X가 크롤링 차단이라 원문 확인 불가.
- 시도한 해결 방법: 접근 가능한 옵시디언 포럼·Substack으로 대체, 8건 확보.
- 효과 또는 실패 여부: 인용 5개 이상 기준은 충족. 단 한국어 커뮤니티 발언은 미확보.
- 실패 후 다음 대처: 문서에 한계·후속 과제로 명시(브라우저 기반 재조사 필요).
- 해결여부 & 남은 과제: 부분 해결. 잔여 과제는 prd.md 조건부 합격의 보완 항목(M3 전까지)으로 편입.

### 시행착오 2: 시장 규모 가정이 검증에서 절반으로 깎임

- 겪은 어려움: SAM의 "기록 습관 보유 10~20%" 가정이 감으로 잡은 값.
- 시도한 해결 방법: 사용자 지시로 독립 프록시(Milanote 유료 고객, Eagle 사용자 수) 교차 검증.
- 효과 또는 실패 여부: 가정 A 부분 반박 → 5~10%로 하향, SAM 300만~600만 → 150만~300만. 가정 B(옵시디언 내 3~5%)는 유지.
- 실패 후 다음 대처: 검증 과정·출처를 market.md "가정 검증" 섹션으로 남겨 추적 가능하게.
- 해결여부 & 남은 과제: 데스크 검증은 완료. 직접 설문·랜딩페이지 전환율 검증은 MVP 단계 과제.

### 시행착오 3: 문서 편집 실수 2건 (헤더 삭제, 섹션 순서)

- 겪은 어려움: decisions.md 편집 중 2026-08-07 헤더 삭제, market.md에 3.5가 3.4 앞에 삽입.
- 시도한 해결 방법: diff 재확인으로 발견 → 헤더 복구, 파이썬 스크립트로 섹션 재정렬.
- 효과 또는 실패 여부: 둘 다 커밋 전후로 잡아 수정 완료.
- 실패 후 다음 대처: 문서 구조를 바꾸는 편집 뒤에는 diff·헤딩 목록 확인을 습관화.
- 해결여부 & 남은 과제: 해결. Copilot 리뷰가 추가로 잡은 것(중복 불릿, 결정 ID 부재, PRD 결번)도 모두 반영.
