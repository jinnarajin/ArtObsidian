### 3.2 명문화한 요구사항과 명문화하지 않은 부분

명문화한 부분

- 산출물 파일·양식·완료 기준(출처·인용 수), 승인 게이트, 브랜치·PR 규칙, 공통 P0 고정 3종

명문화하지 않은 부분

- 시장 크기 분석(TAM/SAM/SOM), 타겟 지역, 문서의 언어 톤, 수익 모델·마케팅 전략

### 3.3 명문화하지 않은 부분에 대한 AI의 해석

- 도움이 된 가정: 이미지 P0 승격 제안(리서치 근거 기반), Apple 메모를 "기본값 대안"으로 분석, 구독 장벽을 제3자 비용 리스크로 구분.
- 의도와 다르게 해석된 것: 보고서 어투를 번역투 한국어로 작성("1급 시민" 등), 시장 규모 분석을 양식에 없다는 이유로 생략, 검증 보완을 국내 한정으로 잡음.
- 다음에 명문화할 것: 언어 톤(쉬운 한국어 — 메모리에 규칙화 완료), 양식 외 필수 분석 항목(시장 크기), 타겟 지역.

## 6. Guiding Questions — Cognitive Offload (AI에게 넘긴 것과 의도 전달)

### 위임 범위 설정

- AI에게 넘긴 것: 웹 리서치(시장·페인포인트·출시 사례), 양식에 맞춘 문서 초안 작성, 가정의 프록시 검증, 번역투 다듬기, 커밋·PR 관리.
- 사람이 쥔 것: 진행 게이트(중간보고서 승인), 방향 결정(수익 모델, 타겟 지역, 백업 방식), 품질 지적(번역투, 시장 크기 누락, 유료 차트 모순).
- 경계 규칙: 기획은 리서치 리뷰·승인 후에만, 기획서에 없는 기능 임의 추가 금지.

### Context 만들기

- 기준 문서를 프롬프트에 명시(spec.md, 양식 TEMPLATE 2종) — AI가 양식·완료 기준을 그대로 따르게 함.
- 대화 중 확정된 결정을 즉시 decisions.md([D-YYYYMMDD-n])와 메모리(쉬운 한국어 규칙)로 남겨 다음 작업의 컨텍스트로 재사용.
- 서브에이전트에는 확정 결정사항 목록을 프롬프트에 그대로 넣어 재해석 여지를 줄임.

### 결과 검토

- 단계 게이트: 리서치 → HTML 중간보고서 → 사람 리뷰 → 기획. 최종은 PR로 다시 리뷰.
- 사람 리뷰가 잡은 것: Apple 메모 누락, 시장 크기 분석 부재, 국내 한정 타겟, 유료 차트 모순, 번역투 — AI 스스로 못 잡은 것들.
- AI 자체 검토: 가정 비율 프록시 검증(SAM 절반 하향), diff 확인으로 편집 실수 복구, Copilot 리뷰 반영.

### 워크플로우

- 병렬 리서치(서브에이전트 2개) → 승인 게이트 → 기획 에이전트 → 보강 루프(사용자 지적 → 추가 리서치/수정 → 커밋) → PR.
- 산출물은 전부 마크다운 + 브랜치 커밋, 중간 확인은 HTML 보고서로 시각화.
