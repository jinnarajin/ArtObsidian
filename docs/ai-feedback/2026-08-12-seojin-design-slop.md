## 1. AI 사용 중 막힌 지점

- 무엇을 하려던 중이었는가?: "AI 냄새 안 나는 디자인" 만들기. 화이트보드로 두 트랙(레퍼런스 기반 / 방법론 기반)을 계획하고 진행.
- AI는 어떤 응답이나 결과를 냈는가?: 계획 전체(리서치 → 프롬프트 → 생성)를 에이전트로 병렬 실행해 한 번에 완료.
- 기대와 실제의 차이: 결과물 자체는 좋았지만, **리서치 단계는 내가 직접 하면서 배우고 싶었던 부분**이었는데 AI가 통째로 대신해버림. 진행 속도와 학습 기회가 트레이드오프였음.
- 문제의 원인: 프롬프트(나의 지시 방식). "진행해볼까"라고만 해서 어디까지 위임할지 경계를 정하지 않음.
- 판단 근거: AI는 지시받은 계획을 정확히 수행함. 학습용 단계와 위임용 단계를 구분해서 말하지 않은 것이 원인.

## 2. 지식 수준에 따른 토큰 소비량과 소요 시간 비교

### 2.1 잘 아는 분야 작업

- 작업 내용 / 토큰 소비량 / 소요 시간: 디자인 방향 판단(3안 중 선택, "AI 느낌 안 남" 평가) — 토큰 거의 0, 즉시 판단. 사람이 한 유일한 단계이자 가장 중요한 단계.

### 2.2 모르는 분야 작업

- 작업 내용 / 토큰 소비량 / 소요 시간: AI slop 회피 방법론 리서치(에이전트 2개, 약 9만 서브에이전트 토큰, 각 2분대) + 목업 생성(에이전트 5개, 약 24만 토큰, 각 1.5~2.5분).

### 2.3 차이 분석

- 리서치·생성은 전부 에이전트에 위임되어 내 시간은 대기뿐. 차이를 만든 요인은 지식이 아니라 **위임 범위 결정**.
- 잘 아는 분야(취향 판단)에서는 3안을 보자마자 결정 가능.
- 모르는 분야(slop 방법론)는 검증 없이 AI 결과를 수용 — 이 부분이 학습 손실 지점 (섹션 6 참고).

## 3. 프롬프트 작성과 AI의 해석

### 3.1 실제 프롬프트

```
[최초 프롬프트]
(화이트보드 스크린샷 첨부) 지금 이렇게 오늘 하려고 하는데 이슈파줘
그래 지금 오늘 할거야. 진행해볼까
```

```
[주요 수정 프롬프트]
오 근데 내가 리서치하고 보고 싶었는데 내가 배울 수 있는 부분이
리서치하고 어떻게 하면 ai 느낌안나는 방법을 할지 찾을 수 있는거 아니야?

프롬프트 검증 실험 — 공통 프롬프트에서 금지 목록을 빼고 한 번 더 생성해서,
정말 slop이 나오는지 직접 확인해보기. 이거 해보고 싶어
```

### 3.2 명문화한 요구사항과 명문화하지 않은 부분

명문화한 부분

- 화이트보드의 두 트랙 계획 (레퍼런스 찾기 → 프롬프트에 넣기 → 여러 초안 생성 후 고르기 / slop 회피법 검색 → 적용 → 생성)

명문화하지 않은 부분

- 리서치를 누가 하는지 (나의 학습 단계인지, AI 위임 단계인지)
- 초안 개수, 스타일 방향, 산출물 형식(HTML 목업)

### 3.3 명문화하지 않은 부분에 대한 AI의 해석

- 도움이 된 가정: 초안 3개를 서로 다른 스타일 앵커로 생성한 것, 금지 목록을 프롬프트에 명문화한 것, HTML 목업 형식(이전 회고의 "html로 중간중간 확인하기" 반영).
- 의도와 다르게 해석된 것: "진행해볼까" = 전 단계 위임으로 해석 → 리서치까지 AI가 수행.
- 다음에 반드시 명문화할 것: **"이 단계는 내가 직접 한다"는 학습 경계.**

## 4. 시행착오 과정

### 시행착오 1: 리서치 위임으로 학습 기회 상실

- 겪은 어려움: 계획 전체를 AI가 실행해버려 "slop 회피법을 찾는 과정"에서 배울 기회가 사라짐.
- 시도한 해결 방법: (1) AI 리서치 문서를 답안지로 쓰고 직접 검색 후 비교, (2) 원본 소스 직접 읽기, (3) 프롬프트 검증 실험 — 세 가지 복구안 중 3번 실행.
- 효과 또는 실패 여부: 대조군 2종(A 금지목록 제거 / B 막연한 프롬프트)을 만들어 금지 목록의 효과를 눈으로 비교할 수 있게 됨.
- 실패 후 다음 대처: Claude 메모리에 "리서치·탐색 단계는 사용자가 직접, AI는 비교·보완 역할" 규칙 저장.
- 해결여부 & 남은 과제: 부분 해결. 대조군 채점(slop 체크리스트로 몇 개 해당되는지)은 아직 안 함.

### 시행착오 2: 대조군 실험의 변수 분리

- 겪은 어려움: "금지 목록을 빼고 생성"만 하면 변수가 하나가 아님 (frontend-design 스킬 자체도 slop을 회피함).
- 시도한 해결 방법: 대조군을 2개로 분리 — A는 조건 동일 + 금지 목록만 제거, B는 막연한 프롬프트 + 스킬 미사용.
- 효과 또는 실패 여부: B가 기준선, A가 금지 목록 단독 효과를 보여주는 구조가 됨.
- 해결여부 & 남은 과제: 구조는 완성. 채점과 결론 정리가 남음.
